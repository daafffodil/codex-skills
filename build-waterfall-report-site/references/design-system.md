# 瀑布流站点设计与交互规则

## 核心体验

- 用户在一个页面内完成浏览，不需要反复进入和退出详情页。
- 折叠卡片只显示分类／地区和标题；完整内容在原卡片内展开。
- 页面首先服务于信息获取，其次才是视觉风格。
- 保持白底、清晰留白和轻量品牌感，不做杂志式装饰堆叠。

## 页面结构

1. 最小页眉：可选Logo＋项目名。
2. 日期型站点：前一天、当前日期、后一天；点击日期打开月历。
3. 瀑布流：桌面3列、平板2列、手机1列。
4. 卡片：分类、标题、展开按钮、完整正文。
5. 默认不放页尾；用户确实需要法律或联系信息时再增加。

无日期内容集隐藏日期导航。不要为了填满页面添加口号、介绍段、更新时间、栏目标签或额外导航。

## 品牌标识

- 铛铛一下网页优先使用 `assets/brands/dangdang-brand-mark.png`，保持透明背景和原始比例。
- 需要完整品牌署名时使用 `assets/brands/dangdang-logo.png`。
- 页眉标识建议显示为34—40px；它是识别入口，不做巨型装饰。
- 不重绘、不改色、不拉伸，也不从截图或生成图中重新抠取Logo。
- 非铛铛一下项目不自动带入该Logo，改用项目自己的品牌标识。

## 视觉变量

推荐默认值：

```css
:root {
  --ink: #171a18;
  --muted: #686d68;
  --line: #e2e5e0;
  --paper: #ffffff;
  --accent: #23b985;
  --tone-green: #dff3e7;
  --tone-yellow: #fff0b8;
  --tone-violet: #e9e5fa;
}
```

- 正文字体使用系统无衬线字体。
- 卡片圆角18—22px，边线1px。
- 卡片色块最多使用3种低饱和色，正文卡片可以保持白色。
- 阴影仅用于月历等浮层，卡片本身通常不加阴影。
- 不使用大面积渐变、玻璃拟态、装饰性英文、彩色竖条和无意义图标。

## 卡片规则

- `summary`最小高度约124—148px。
- 标题桌面约20px，手机约19px。
- 正文约13—15px，行高1.7—1.85。
- 展开后用一条浅色分隔线区分标题与正文。
- 完整保留段落、列表、来源链接和事实限制。
- 总结、建议和跟踪信号按普通卡片处理，不另建复杂页面。

## 日期与月历

- 当前日期字号要明显，但不做巨型Hero。
- 前后按钮使用简单圆形按钮。
- 月历只让有内容的日期可点击；当前日期使用品牌色。
- 切换日期后更新URL和浏览器历史。
- 不使用笨重的日期下拉列表。

## 无障碍和响应式

- 优先使用原生 `<details><summary>`。
- 为按钮提供中文或项目语言的 `aria-label`。
- 键盘焦点清晰可见。
- 920px以下切到2列，680px以下切到1列。
- 在360px宽度检查无横向滚动、标题不截断、月历不超出视口。

## 禁止项

- 点击卡片跳到另一个详情页；
- 折叠卡片重复显示摘要、时间、作者和装饰标签；
- 国家或分类名称后附加“动态”“栏目”等多余词；
- 恢复用户已删除的编辑说明、补录说明、页尾版权或空泛介绍；
- 用复杂框架掩盖一个静态站点就能解决的问题。
